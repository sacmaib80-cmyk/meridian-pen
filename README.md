# MERIDIAN ONE

เว็บขายปากกาดิจิทัล แบบ scroll-driven 3D เรนเดอร์สดด้วย WebGL2

```
cd meridian-pen
node scripts/serve.cjs 4180      →  http://127.0.0.1:4180/
```

ไม่มี build step ไม่มี dependency ตอนรัน (puppeteer ใช้เฉพาะสคริปต์ตรวจงาน)

### แสง = IBL ที่ปั้นเองตอนโหลด (ไม่ใช่ฟังก์ชัน analytic แล้ว)

ไปวัด **activetheory.net/work** กับ **iyo.ai/iyo-one** ด้วย `webstudy/probe.js` แล้วเจอว่า
IYO ใช้ `MeshPhysicalMaterial` เต็มสูบ — **envMap · roughness · metalness · normalMap · aoMap ·
iridescence · transmission · clearcoat · anisotropy · sheen** + ACES + LUT
ช่องว่างใหญ่สุดของเราคือ **เขาให้แสงจาก environment map จริง เราใช้สมการ**

`js/env.js` เลยปั้น IBL ขึ้นมาตอน startup:

1. วาดสตูดิโอลงหกหน้าของ cubemap (softbox เป็น**สี่เหลี่ยมมีขอบจริง** ไม่ใช่ `pow()` ที่ไม่มีขอบ + เส้นขอบฟ้า)
2. **GGX importance-sample** ไล่ทำ mip chain — mip 0 = กระจกเงา, mip สุดท้าย = irradiance
3. ตอนเรนเดอร์แค่ `textureLod(env, R, roughness * maxLod)`

**ยังไม่มีไฟล์ภาพ** — cubemap วาดด้วยโค้ด · ที่เปลี่ยนคือ roughness ถูกแก้ด้วย mip chain
แทนที่จะแก้ด้วยเลขยกกำลังที่จูนมือ ซึ่งเป็นเหตุผลที่โลหะอ่านถูกทุกค่า roughness ไม่ใช่แค่สองค่าที่จูนไว้

**แล้วมันเร็วขึ้นด้วย** — 2 texture fetch แทน pow/exp กองใหญ่ที่เคยรันได้ถึง 3 รอบต่อ fragment

### ผ่าดูข้างใน (บท 3)

ลิ่มของเปลือกถูก `discard` ในเชดเดอร์ตามมุมรอบแกน แล้วทำ 3 อย่างที่ขาดไม่ได้:

1. **ตัดเฉพาะโซนเปลือก** (0-6) ไส้ในกับคลิปไม่โดน
2. **ปิด backface culling** ตอนเปิดลิ่ม — ผนังด้านในกลายเป็น backface ถ้าไม่ปิดจะเห็นเป็นที่ว่าง
   แล้วให้ผนังในมีวัสดุของตัวเอง (อะลูมิเนียมพ่นทราย ไม่ใช่โลหะขัดเงาด้านนอก)
3. **ขอบรอยตัดสว่างเป็นอะลูมิเนียมเปลือย** — เปลือกเป็นผิวหนาศูนย์ ถ้าไม่ทำขอบ มันจะจบเป็นเส้นผมและอ่านเป็นกระดาษ

ลิ่มหมุนตาม `rotY` เสมอ (`cutAngle = rotY + π/2`) เลย **เปิดค้างหันหากล้องแม้ตอนลากหมุนเอง**

ของข้างในเป็นเรขาคณิตจริง 4 ชิ้น: sensor (lathe) · PCB (กล่อง มีลายทองแดงในเชดเดอร์) · cell (lathe มี wrap) · USB-C (กล่อง)

### ฉากหลัง

ฝุ่นลอยในอากาศสตูดิโอ 420 เม็ด — `gl.POINTS` 1 draw call วาดเข้า HDR target **ก่อน** resolve MSAA
เลยได้ทั้ง antialias และเข้า bloom เอง · depth test เปิด / depth write ปิด → ปากกาบังเม็ดที่อยู่ข้างหลังจริง
ขนาดเม็ดเป็นรัศมีมิลลิเมตรแล้ว project จริง (`aRnd.x * uSizeK / dist`)

### ลูกเล่นตัวหนังสือ

หัวเรื่องถูกหั่นเป็น span ต่อตัวอักษร ใส่ไว้ใน **mask ระดับคำ** แล้วเลื่อนขึ้นมาจากหลังขอบ
stagger ทำด้วย `transition-delay: calc(var(--i) * 26ms)` **ไม่ใช่ JS ต่อเฟรม** → ไม่กิน render loop และหลุด sync ไม่ได้
ตัวเลขใน `.figure` กับราคาวิ่งนับขึ้นตอนบทมาถึง · แถวสเปกกับ meta ไล่เข้าทีละแถว

## ตัวเลขที่วัดจริงบนเครื่องนี้ (GeForce GT 710, การ์ดปี 2014)

```
buffer          ก่อนใช้ IBL      หลังใช้ IBL
1600x950        16.6ms   0%      16.7ms   0%
1920x1080       16.7ms   0%      16.7ms   0%
2560x1440       18.6ms  26%      16.7ms   0%   ← หายกระตุก
2880x1620       22.6ms  33%      16.7ms   0%   ← หายกระตุก (เพดาน DPR 1.5)
3840x2160        125ms 100%      42.9ms  94%   ← เร็วขึ้น 3 เท่า แต่การ์ดใบนี้ยังไม่ไหว
```

**IBL ทำให้เร็วขึ้นไม่ใช่ช้าลง** — ที่ 2880x1620 จาก 22.6ms/กระตุก 33% เหลือ 16.7ms/0%

**พูดตรงๆ เรื่อง 4K:** ตัว renderer เรนเดอร์ 4K เนทีฟได้จริงเพราะไม่มี texture ให้ upscale
แต่ **GT 710 ในเครื่องนี้รัน 4K ไม่ไหว** (8fps)

ระบบ adaptive resolution จับได้แล้วไล่ลดให้เอง — ทดสอบโดยบังคับ 4K:

```
t=1s   3840x2160  scale 1.00
t=4s   3379x1901  scale 0.88
t=8s   2443x1374  scale 0.64
t=14s  1921x1081  scale 0.50   ← กลับมาลื่น
```

## ระบบภาพ

**ฟอนต์เดียวทั้งเว็บ** — Archivo variable ใช้ 2 แกน (น้ำหนัก + ความกว้าง)
เว็บอ้างอิงที่ typography ดีที่สุดใน `webstudy/` (lacoste, lusion) ก็ใช้ฟอนต์เดียวเหมือนกัน

**scale มีรูตรงกลางโดยตั้งใจ** — ไม่มีอะไรอยู่ระหว่าง 17px กับ 54px
ตัวเล็ก = ข้อมูล ตัวใหญ่ = น้ำเสียง ไม่มีที่ให้หัวเรื่องหย่อนลงไปนอนตรงกลาง

**สีเน้นสีเดียว** — ทองเหลืองของแหวนสลัก และหมึกที่ปากกาเขียนก็เป็นสีเดียวกันนั้น
สีเย็นในเฟรมไม่เคยเป็นสี UI มันโผล่ได้เฉพาะตอนเป็นแสงสะท้อนบนโลหะ

## รอบ 4 — คืนรายละเอียดให้โหมดกดดูชิ้นส่วน

พอชิ้นส่วนถูกซูมมาเต็มจอ ทุกอย่างที่ปรับไว้สำหรับ "มองปากกาทั้งด้ามที่ระยะแขน" กลายเป็นหยาบหมด

| อาการ | ต้นเหตุ | แก้ |
|---|---|---|
| ขอบเป็นเหลี่ยม | `RADIAL 144` = ~6px ต่อด้านตอนซูม · ไส้ใน `RS 40` | 216 / 120 |
| ตัวอักษรสลักเบลอ | atlas 2048×128 คลุมเส้นรอบวงทั้งวง แต่เห็นทีละ 1/6 = 340 texel ต่อ 400px | 4096×256 + anisotropic 16× |
| สลักอ่านเป็นสติกเกอร์ ไม่ใช่รอยกัด | บิด normal ตาม **ค่า** ของ texture | บิดตาม **เกรเดียนต์** ของมัน → ผนังร่องรับแสงได้ |
| ผิวเรียบเหมือนพลาสติก | ความถี่ brush/scratch ตั้งไว้สำหรับภาพกว้าง | ชั้น octave ละเอียดที่เปิดด้วย `uDetail` |
| ไส้ในเป็นกรวยเทาเปล่า | ไม่มีวัสดุจริงเลย | บอดี้กลึง + แถบ potting ดำด้าน + ฟอยล์เกจแบบ serpentine + ปลอกเหล็ก |

**และเพิ่มความละเอียดจริงด้วย supersampling** — โหมดนี้วาดแค่ 1 ใน 11 ชิ้น ต้นทุน fragment จึงเหลือน้อยมาก

⚠️ **ดัน `dprCap` ไม่ช่วยอะไรบนจอ DPR 1** เพราะหน้าเว็บใช้ `min(cap, devicePixelRatio)` — ต้องคูณที่ backing store ตรงๆ

### 🔴 บทเรียนของรอบนี้

**1. วัดก่อนโทษ** — เฟรมตกเหลือ 40-62ms ตอนเปิด inspector · A/B แล้วพบว่า **ชั้นดีเทลในเชดเดอร์ฟรี**
(16.7ms / 0 jank) ตัวที่กินคือ supersample 2.0 ล้วนๆ ถ้าเดาคงไปรื้อเชดเดอร์ที่ไม่ได้ผิดอะไร

**2. อ่าน headroom จาก frame time ไม่ได้บนจอ vsync** — เฟรมที่เสร็จใน 4ms กับ 15ms รายงาน 16.7 เท่ากัน
กฎ *"ไต่ขึ้นถ้า median < 15.4"* จึงไม่มีวันเป็นจริง สิ่งเดียวที่สังเกตได้คือ *"ยัง lock vsync อยู่ไหม"*
→ ไต่ทีละขั้น ตกทันทีที่หลุด
(ความผิดคลาสเดียวกับการจับเวลาใน rAF callback: เครื่องมือมองไม่เห็นสิ่งที่มันควบคุมอยู่)

**3. ตัวคุมต้องกันสัญญาณรบกวนที่ตัวเองสร้าง** — ทุกครั้งที่เปลี่ยนขั้น render target ถูกสร้างใหม่ = เฟรมสไปก์
สไปก์นั้นถูกอ่านว่าโหลดเกิน → ลดขั้น → สไปก์อีก วนไม่จบ
ต้อง (ก) quantise scale เป็น 1/16 (ข) ล้างหน้าต่างวัดหลังเปลี่ยนขั้น (ค) ตัดสินเฉพาะตอน transition จบแล้ว
👉 **ผลข้างเคียงที่ไม่ได้ตั้งใจ: การ quantise ทำให้ p95 ของการสโครลทั้งหน้าดีขึ้นจาก 63.6ms เหลือ 23.2ms**
เพราะเดิม `renderScale` lerp ทีละนิดทำให้ realloc ทุกเฟรมที่สโครล

**4. ratchet ต้องฟื้นได้ แต่ต้องปันส่วน** — เพดานถาวรทำให้เครื่องสะดุดครั้งเดียวกดคุณภาพทั้ง session
แต่ปล่อยให้ลองใหม่ทุก 15 วิ = ภาพเปลี่ยนความคมวนไปมา · ลงตัวที่ **retry ได้ 2 ครั้ง ห่างกัน 40 วิ**

**5. 🔴 เชดเดอร์ยาวมีหน้าผา** — ลองเพิ่มรอยปาดหน้าบนหน้าตัด (แค่ 2 sin + length)
เฟรมตกจาก 16.7 เป็น **33-83ms ที่ความละเอียดเดิม** = ไม่ใช่ปัญหา fill rate แต่ข้าม occupancy cliff
**ถอนออกแล้ว** — รายละเอียดระยะใกล้มีงบคำสั่งที่ตายตัวกว่าที่ octave ก่อนหน้าทำให้เข้าใจไปมาก
